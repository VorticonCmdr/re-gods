# GODS reverse-engineering tooling

- **Ghidra MCP** (`mcp__ghidra__*`) — a project named `gods` is already open with `GAME.EXE` and `GODS.EXE` analyzed. **Multiple programs are open: always pass `program=` explicitly**, or calls silently target the active one. 16-bit real-mode code references strings via DS-relative immediates, so `get_xrefs_to` on a string address usually returns nothing — use `search_instructions` with the offset as an operand pattern instead.
- **DOSBox MCP** (`mcp__dosbox__*`) — works, with caveats. **Start it with `mcp__dosbox__bridge_start`, not by shelling out to the binary directly.** The bridge's config (`~/Library/Application Support/dosbox-mcp/config.toml`, human-edited only — `bridge_setup` refuses to touch `binary`) already points `binary` at the debug build (`.../dosbox-automation/build-debugger-noabort/dosbox_with_debugger`), so `bridge_start` spawns the correct debugger-capable instance and attaches to it in one call — no manual `nohup`/background-process juggling, and no risk of a second, untracked process the bridge doesn't know about. (An earlier revision of this note said the opposite — that `bridge_start` spawns a non-debug build and to launch `dosbox_with_debugger -noautoexec` directly instead. That was true against a different config at the time; it no longer is. If `bridge_start` ever again yields a build without breakpoint support, that's a config problem to fix in `config.toml` — `bridge_status`/`dosbox_status(detail:true).info.capabilities.debugger` shows whether the attached engine has it — not a reason to launch the process by hand.) The engine writes its API token to `~/Library/Preferences/dosbox-automation/webserver/api_token` only when `DOSBOX_API_TOKEN` is *absent* from its environment (`src/webserver/webserver.cpp:537`, `webserver_token_file = on`); this only matters if you ever do launch it manually. **Port 8386 is sometimes used by something outside this session** (instances have appeared and exited unprompted); if a call gets connection-refused, check `lsof -iTCP:8386` before assuming a local fault.
- **Layout.** The shipped files are in `game/` (the DOSBox `C:` mount; a live session may rewrite `game/HISCORES.BIN`). The Ghidra project is `ghidra/gods.gpr`. Derived listings are in `analysis/`.
- **The port** (`src/`, vanilla ES modules + Vite). `npm run dev` serves `game/` as-is, still DCL-compressed; the port decompresses in the browser, so every format claim is exercised against the original bytes. The node tools read `game/` too. Three headless tools make its claims checkable without a browser: `node tools/verify-node.mjs` runs the whole invariant suite, `tools/hero-sheet.mjs` renders the exact sprites the state machine selects, and `tools/frame-node.mjs` composites a full game frame. **The verification panel has caught real errors in this document** — the `.PI1` palette claim, the fact that idle/fall render through the remap table rather than their raw `anim_base`, and now the difficulty-scalar direction. The suite **prints its own totals** — currently `459 assertions + 29 notes = 488 rows` — which is the figure to quote here. ⚠️ **That number has now gone stale twice.** An early revision carried a hand-derived grep count that under-read it by six (six rows print with different leading whitespace); it was then corrected to the tool's own figure and left at `414` right through the trigger-ACTION-verb pass that added 32 assertions. **Run the tool; do not copy this number out of this file.** It is mutation-tested (`npm run verify` runs `tools/lint-checks.mjs` first, which fails the build on an assertion where both sides are constants this project wrote). `src/game/frame.js` exists solely so the **per-tick call order** is code a check can drive: while it was inline in `main.js` a mutation that swapped the projectile step and the player tick **survived the entire suite**. ⚠️ **The panel and the headless tool are STILL not the same set — the gap is 9 rows** `[PROVEN]`. Both run the identical check *groups* (`runAllChecks` plus the seven named exports, `main.js:249`–`257` against `verify-node.mjs`), and that part really was fixed: previously six groups were node-only, so the page reported a subset of the groups and a regression in any of them was invisible where the panel is supposed to catch it. But `verify-node.mjs` **also emits 6 assertions and 3 notes written inline in the tool itself** — the nine `tally()` calls outside `line()` — covering the jump-table symmetry, terminal fall speed, tile slicing, the event-probe rounding proof and both camera checks. Those live in no group, so no browser can reach them: **the page shows 479 of the 488 rows.** Measured by re-running exactly the panel's own set: **71–99 ms warm**, so the redundant per-group decompression is still not worth caching (`fetchRaw` already memoizes the fetch side). ⚠️ That timing is a **node** measurement of the panel's set, not a browser one — the original `119 ms` figure was never re-measured in a browser this pass.
- **`tools/blast.py`** — working PKWARE DCL decompressor. `python3 tools/blast.py game/<files>` reports the decompressed size and always writes `out_<name>` for each file into the working directory (or `$BLAST_OUT`), regardless of argument count — see `analysis/README.md`.
- **CodeGraph** — not initialized for this project (no `.codegraph/`). The port in `src/` could be indexed now; the game itself has no source.
